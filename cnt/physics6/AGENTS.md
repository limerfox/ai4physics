# AGENTS.md — учебное исследование с графом проекта

## 0. Цель и образ результата

Ответить на вопрос: точно точное решение свободного массивного скалярного поля в пространстве-времени де Ситтера воспроизводит соответствующее решение в пространстве-времени Минковского при стремлении кривизны к нулю при использовании разных численных методов.

Используемые методы:
* `float64`: сравнение с низкой точностью; вычисления проводятся с использованием 17 десятичных знаков, после чего результат округляется до типа `complex` в Python (binary64). Поскольку стандартная функция для вычисления функций Ганкеля в библиотеке SciPy не поддерживает чисто мнимый порядок (который возникает при малых значениях $H$), данный метод выступает лишь в качестве аппроксимации, а не полноценной реализации функций Ганкеля в формате binary64.
* `mpmath`: то же самое выражение для функции Ганкеля, вычисленное с произвольной точностью.
* `asymptotic`: адиабатическое приближение (или приближение ВКБ) первого порядка по параметру $H$, полученное из разложения $\omega_H(t)=E_k-k^2tH/E_k+O(H^2)$. Это не является полным равномерным разложением Дебая для функции Ганкеля; данный метод включен исключительно как четко определенный асимптотический эталон для сравнения.

В конце работы в проекте существуют:
* `results/runs.csv`: таблица со столбцами `(method, m, k, n_H, H_max, H_min, n_t, x, t_ref, dps, fit_last_n, run_id, run, H, max_relative_error, status, message)` и всеми результатами и параметрами, от которых зависели результаты.
* `results/summary.csv`: оценочный логарифмический наклон для каждого и rmse `(method, m, k, n_H, H_max, H_min, n_t, x, t_ref, dps, fit_last_n, run_id, run, p_estimate, log_fit_rmse, n_valid)`.
* `results/run_config.json`: полный набор конфигураций.
* `results/run_config.csv`: полный набор конфигураций.

## 1. Критерий готовности

После выполнения файла run_experiment.py проверка полного расчета завершается корректно:
```bash
python checks/check.py --output results
```

Шаги глубины. Следующий шаг запускается, только если преоверка предыдущего завершилась корректно.

| Шаг | Команда | Условие перехода к следующему шагу | Время |
|---|---|---|---|
| Пробный прогон | сборка плана | все конфигурации (m,k) заданы, имена прогонов не повторяются | доли секунды |
| Короткая проверка | несколько значений (H) при фиксированных (m,k) для каждого метода | ошибка демонстрирует ожидаемое асимптотическое поведение, вычисления устойчивы | секунды |
| Полный расчёт | все комбинации метода, (m,k) | все прогоны в журнале, правило принятия выполнено | несколько минут |

```bash
python checks/check_plan.py --output results
python checks/check_quick.py --output results
```

Правило принятия (записано до запуска):

1. **Метрика и единицы:** относительная безразмерная ошибка между решениями после удаления общей (H)-зависимой фазы: [\epsilon(H)=\left|\frac{\phi_{dS}(H)}{\phi_M}-1\right|].
2. **Повторы:** вычисления детерминированы; повторный запуск одной конфигурации должен давать тот же результат с точностью до численного допуска.
3. **Сравнение:** для каждого метода вычисляется (p) из зависимости [\log\epsilon = p\log H+C] и сравнивается с теоретическим значением (p=1) с погрешностью \pm 0.2.
4. **Практический порог:** невозможно предварительно оценить, поскольку неизвестна вычислительная ошибка каждого метода.
5. **Выбор варианта:** метод считается более точным, если при одинаковых входных параметрах он даёт меньшую ошибку, коэффициент (p) метода даёт значение ближе к истинному, сохраняет устойчивость при уменьшении (H). Выбор производится по всем значениям (H).
6. **Разбиение для вывода:** метод считается прошедшим проверку, если ошибка стремится к нулю при (H \to 0), а измеренный порядок сходимости согласуется с аналитическим предсказанием с точностью до погрешности. Если метод не позволяет исследовать достаточно малые (H) из-за потери точности, это фиксируется как ограничение метода, а не как опровержение физического предела.

- Эксперименты запускаются только через `run_experiment.py`; результаты пишутся в
  `results/`.
